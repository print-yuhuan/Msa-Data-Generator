## DeepSeek 真实服务

接口：`https://api.deepseek.com`。主要模型：`deepseek-flash`；对照评价模型：`deepseek-v4-pro`。非流式、JSON 模式、低温度配置；请求统一串行，前次完成至下一次开始至少间隔 10 秒。测试密钥只以当前 Windows 用户的 DPAPI 密文保存在本机测试配置中，不记录到本文件、源码或响应报告。

| 场景 | 实际行为 | 结果 |
| --- | --- | --- |
| 缺少规格与尺度 | 返回 `clarify`，要求补充条件，不按空约束直接生成 | 通过 |
| 一句话配置 Xbar-R 研究 | 返回最小配置补丁，本机生成 90 次测量并复核约束 | 通过 |
| 多轮切换 ANOVA | 只调整分析方法/交互策略，保留设计、规格、精度、种子与其它约束 | 通过 |
| 确定性约束冲突 | 返回 `diagnose`，解释 GRR 不小于 EV 的关系，等待用户确认修改 | 补测通过 |
| 超出支持范围的人数 | 明确不支持 4 名操作员，不擅自改成 3 名后执行 | 通过 |
| Flash 结果评价 | 返回 `evaluate`，引用本机指标、ANOVA 交互项和模拟数据限制 | 通过 |
| Pro 同数据评价 | 返回相同协议的 `evaluate`，本机数值映射一致 | 通过 |
| 评价连续追问 | 解释 GRR/TV 与 P/T 的分母差异，不修改或重新生成数据 | 通过 |

生成要求为：3 名操作员、10 件部件、每件重复 3 次，规格 9～11，4 位小数，种子 123；GRR/TV ≤ 20%、P/T ≤ 20%、ndc ≥ 5，EV/AV 不设约束。参数、约束模式、记录数和多轮保留行为均已核对。

## 测试中发现并修复的问题

1. 首次真实调用中，Flash 在严格规格模式缺少全部规格限及尺度时返回了 `generate` 空补丁。界面原有校验已阻止执行；本轮进一步增加本机 `generation_readiness`，并在接收生成回复时执行完整 `validate_request`。修正后同类请求正确澄清。
2. 初次诊断文字把 EV ≥ 80%、GRR ≤ 10% 的确定性矛盾泛化成“有限搜索不证明无解”，并建议调整对上下界约束无效的默认误差。新增失败类别，明确区分逻辑冲突和搜索耗尽，补充 GRR/EV/AV 关系及误差适用模式。补测正确说明增加预算、换种子或调整默认误差都不能修复该矛盾。
3. 测试入口最初使用窄字符参数，在 Windows 中文工作区路径下失败；改为宽字符入口后，中文配置与报告路径通过。

以上真实用例包含初测和修正后的针对性回归，不能把不同阶段合并成一次无失败执行。最终本地三项 CTest 是在最后构建后统一运行的。
