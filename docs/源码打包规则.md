# 源码打包规则

源码归档由 `scripts/package-source.ps1` 生成，用于需要单独交付完整源码的场景。Windows 运行包仍由 `scripts/package.ps1` 生成；本脚本不会上传文件或调用 GitHub。

## 执行条件

在已克隆的 Git 工作区中执行，并先用 CMake 生成对应构建目录的 `release-version.json`。例如：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-source.ps1 -BuildDirectory build
```

脚本需要本机 Git 和 PowerShell。不能直接在缺少 Git 元数据的源码 ZIP 解压目录中重新运行；此时应先准备 Git 工作区。版本来自指定构建目录，归档及 SHA-256 校验文件输出到项目 `dist` 目录。

## 文件范围

打包清单使用本地 `git ls-files --cached --others --exclude-standard -z`，读取文件时使用当前工作区内容。因此，已跟踪文件的未提交修改、未被忽略的新源码都会进入归档；工作区中已经删除的普通源码不会被旧索引恢复。

清单只允许以下范围：

- 目录：`src`、`tests`、`examples`、`scripts`、`resources`、`licenses`、`patches`、`third_party`、`.github`。
- `docs` 中的 Markdown、JPG 和 PNG 文件。
- 根文件：`CMakeLists.txt`、`LICENSE`、`NOTICE`、`README.md`、`THIRD_PARTY_NOTICES.md`、`dependencies.lock.json`、`.clang-format`、`.gitignore`、`.gitattributes`。
- 额外加入指定构建目录的 `release-version.json`，并在 `licenses` 中保留与根文件一致的项目许可证和 NOTICE 副本。

Git 标准忽略规则（包括嵌套 `.gitignore`、`.git/info/exclude`）对未跟踪文件生效。仓库现有规则排除 `.env`、`ai_settings.json`、临时文件、缓存和诊断目录；`.env.example` 等显式例外仍可保留。与 Git 一致，`.gitignore` 不会自动排除已被跟踪的文件，因此凭据不得加入 Git 索引。

归档不会跟随符号链接或目录联接，不支持以子模块目录替代已展开的第三方源码。项目所需第三方源码和资源应直接保存在上述目录中。归档中的路径去重，专用目录内的项目许可副本以根目录的完整正文为准。

## 失败保护与验证

必需根文件缺失、Git 清单失败或路径校验失败时，脚本直接停止。源码内容先写入临时 ZIP，成功完成归档并计算 SHA-256 后才替换目标文件；若校验文件无法发布，则回退 ZIP。正常结束和受控失败会清理临时文件，已有包不会被清单收集或归档读取错误截断。

`tests/test_source_package.ps1` 在独立的中文路径临时仓库中验证文件纳入、忽略规则、未提交修改、未跟踪新增、已跟踪删除、许可副本、校验值及失败保护。测试仅使用伪造私密标记，不读取真实密钥，不执行联网操作。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_source_package.ps1 -OutputDirectory build/source-package-test-output
```
