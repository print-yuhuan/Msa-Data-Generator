# 验证说明与复现入口

本页介绍 Windows x64 Release 的回归测试、独立公式核算和外部软件对标。请在指定构建目录运行对应测试，并记录配置、平台和二进制 SHA-256。配置字段与统计口径见[使用说明](使用说明.md)和[配置参考](配置参考.md)。

## 统计判据与基准

`tests/fixtures/minitab_baseline.json` 使用 Minitab 22.6 交叉量具 R&R 的 Xbar-R 结果作为基准。随附研究配置使用当前格式，参考测量矩阵及指标保留原始对标数值。基准文件的 SHA-256 如下。

`D8D50706BFCD301E74622467E1984317EBAA04BCA5F632D2402652977C81E9D8`

基准的 sd/studyvar 数组顺序为 GRR、EV、AV、PV、TV。数值判据为`abs(程序值−参考值) <= 1e-11 + 1e-9×abs(参考值)`，ndc 精确比较；Minitab 实测另检查导入测量值的 double 精确相等。该判据只用于跨软件计算回归，不加入用户的目标允许误差。

## 常规测试入口

拉取请求和推送到 `main` 的提交会在托管 Windows 环境构建并运行常规 CTest，覆盖统计内核、CSV、CLI 和 HTML 对比报告。推送 `v*-rc*` 发行候选标签，或在手动工作流勾选 `desktop_regression` 后，还会运行图表导出、窗口渲染、字体与布局回归。桌面作业使用标签为 `self-hosted`、`Windows`、`X64`、`msa-opengl` 的运行器，需要可用的桌面会话、OpenGL 3.3、VS C++、CMake 和 PowerShell；可在对应运行器中用 `ctest -C Release -L 'gui|charts' --output-on-failure` 单独复跑。普通 PR 仅在托管环境执行。

```powershell
.\scripts\build.ps1 -BuildDirectory build -FullTest
```

界面/内嵌资源/渲染及图表导出测试随 `-DMSA_BUILD_RENDER_TESTS=ON` 启用；该选项默认关闭。OpenGL 渲染测试需要可用桌面环境，图表文件导出使用 Windows 图形与内嵌字体。用 `ctest --test-dir build -C Release -N` 查看当前启用项，测试数量取决于构建选项。单 EXE 的窗口及导出验证见[单文件运行验证](单文件运行验证.md)。

常规 Windows 回归需要 PowerShell、本地 Git 和可用桌面 OpenGL 环境。可选的独立公式及图表文件回读脚本需要 Python 3、SciPy、Pillow 和 PyMuPDF，它们不是主程序的运行依赖。

`tests/test_analysis_reference.py` 使用 SciPy 复核置信区间与误分类积分。`--input` 指定已有 CSV，`--cli` 指定被测程序，`--output-directory` 指定证据目录；非默认研究设计可另传 `--config PATH`。未传配置时仍使用 3 名操作员 × 3 次重复 × 10 件部件。配置中的人数、次数、件数须与输入一致。该脚本不启动外部统计软件，不能替代原生软件实测。

## v1.1.3 发布验证

Windows x64 正式候选通过全部 16 项 CTest。Ubuntu 的非图形构建通过全部 5 项核心回归。另用 SciPy 核对 352 项置信限分位数与误分类积分，用 Pillow、PyMuPDF 和 XML 解析器完成 49 项图表文件检查。README 的两条 CLI 示例均使用候选程序实际运行。

Minitab 22.6 对 24 种研究设计完成 240 组实测。标准顺序、全部随机化和操作员内随机化各 90 条记录均与原始研究一致。五软件 ANOVA 对标在相同的 27 组研究上运行 Minitab、JMP、SPSS、MATLAB 和 Origin，共 135 次软件与研究组合，5,776 项数值检查通过。五软件脚本的 `-BuildDirectory` 指定被测构建，输出的 `artifact-binding.json` 记录 GUI 和 CLI 的 SHA-256。

在 Windows 桌面逐项切换六个帮助主题，再从冷启动的程序生成 90 条测量并导出两页方法对比 PDF。首页预览截取自同一发布候选的实际数据页。[查看实机截图](images/ui-preview.png)

## v1.1.1 界面动效验证

Windows x64 发布构建实测覆盖六个主页面、四个选项标签、连续切换操作员人数和开关、反向收起搜索预算，以及切换数据结果标签。重新读取已保存的配置核对了最后一次选择。导入同一份 CSV 后导出的均值控制图 SVG 与原有基准逐字节一致。

为保留测试机的个人设置，在隔离构建中替换了 Windows 动画偏好的读取值，并向实际窗口发送 `WM_SETTINGCHANGE`。逐帧截图显示，同一分段控件在开启、关闭、再次开启时分别出现 28、2、34 个不同位置。关闭时只观察到起点和终点。在展开途中关闭动画，搜索预算直接完整展开；分段选择、展开区域和图表各自稳定两秒后，均未产生额外渲染帧。

在 Intel Graphics、2560 × 1440、240 Hz 显示器上，用带计时探针的同版构建复测均值控制图。客户区为 1920 × 1230 像素，界面缩放为 150%。三轮滚动各 2.4 秒，共采集 1,728 个帧提交间隔，P95 为 4.51 ms，最长 5.11 ms。GPU 绘制 P95 为 2.70 ms。滚动结束并稳定后，连续观察两秒，新增渲染帧为零。下节的历史数据使用 59 Hz 显示器。

## 图表滚动性能

在同一台 Windows x64 机器上对比 v1.0.9 和 v1.1.0 的 Release 构建。使用 Intel Core Ultra 7 265K、Intel Graphics 和 59 Hz 显示器，刷新周期约 16.95 ms。导入 3 名操作员、10 件部件、每人测量 3 次的同一份 CSV，在 1280 × 620 逻辑像素的客户区测试。150% 缩放时实际渲染 1920 × 930 像素。[90 条测量记录的来源](https://github.com/print-yuhuan/Msa-Data-Generator/releases/download/v1.0.7/MSA_Origin_Reference_v1.0.7.zip)

每个场景连续测试三轮，每轮 2.4 秒，以每秒 60 个滚轮事件来回滚动。两版均用相同的测试探针，以异步 OpenGL 时间查询测量 GPU 绘制耗时，用 Windows 高精度计时器记录相邻两次帧提交完成的间隔。下表给出第 95 百分位（P95），以及超过 25 ms 的间隔数占本次采样总数的比例。采样只覆盖滚动期间，正式程序不带计时探针。

| 图表与状态（150% 缩放） | GPU 绘制 P95，旧版 → 新版 | 帧提交间隔 P95，旧版 → 新版 | 超过 25 ms，旧版 → 新版 |
| --- | --- | --- | --- |
| 均值控制图，提示已消失 | 35.69 → 3.28 ms | 36.29 → 17.29 ms | 208/217 → 0/426 |
| 均值控制图，正在显示重算成功提示 | 35.41 → 3.39 ms | 36.30 → 17.31 ms | 208/208 → 0/422 |
| 测量值与部件 | 18.85 → 2.26 ms | 19.51 → 17.31 ms | 1/401 → 0/427 |

在 100% 缩放下，均值控制图稳态 GPU 绘制 P95 由 16.14 ms 降至 1.37 ms，新版的 426 个提交间隔均在 25 ms 以内。重算提示显示期间仍有 1/423 个间隔超过 25 ms。900 × 620 窄窗口开启图表编辑器时也观察到 1/426 个长间隔。相同窄窗口下，数据、选项、帮助页合计 1,277 个滚动间隔均在 25 ms 以内。

旧版给每条线及每段虚线分配了整幅图大小的绘制区域。新版保留相同的顶点、线宽与抗锯齿算法，将范围收紧到笔画及其边缘。150% 下均值图可见区域的截图逐像素比较，RGB 单通道差值最大为 1/255，两版导出的对应 SVG 逐字节一致。

## 可选 Minitab 实测

需要本机已安装且许可可用的 Minitab 桌面版。常规 CTest、程序生成及导出均不依赖 Minitab。

```powershell
# 同一对象只生成一次，三种顺序实际导入Minitab
powershell.exe -NoProfile -NonInteractive -STA -ExecutionPolicy Bypass -File .\tests\test_minitab_run_order.ps1

# 24种设计、8类场景及额外0/10位小数，共240组生成数据
powershell.exe -NoProfile -NonInteractive -STA -ExecutionPolicy Bypass -File .\tests\test_minitab.ps1
```

同组脚本支持`-Config`和`-BuildDirectory`；批量脚本支持`-BuildDirectory`及小范围检查用的`-CaseLimit`。两者使用 Windows PowerShell 的 STA 自动化环境，新建专属 Minitab 实例并在结束时关闭，不修改 CSV 参考文件。每份`.mtb`命令保留分析设置，便于独立复核。

### Minitab COM 对标结果

| 实测 | 范围 | 结果 |
| --- | --- | --- |
| 同组数据的三种导出顺序 | 相同研究以标准顺序、全部随机化、操作员内随机化导出，每份 90 条记录 | 导入行序、StdOrder、标识和测量值精确一致。每种顺序的 21 项 Xbar-R 指标通过，最大绝对误差 2.629008 × 10⁻¹³，ndc 均为 14 |
| 批量导入 | 240 组，24 种研究设计，6 种 CSV 格式，11,250 条测量记录 | 240 组均通过各自适用的比较。P/T 包含 144 组双侧规格，另有 72 组不适用及 24 组单侧规格单独补测 |
| 单侧规格 P/T | 使用同一批次的 24 组原始 CSV，共 1,125 条测量记录。仅设 LSL=2，使用样本均值和研究变异倍数 6 | Minitab 原生单侧与等效容差结果一致。与程序的 P/T 最大绝对误差为 1.563194 × 10⁻¹³ 个百分点，出现在 3 名操作员 × 3 次 × 9 件的研究 |

单侧补测使用 Minitab 22.6 的 `GAGERR` 命令分别传入原始下限和按该组测量均值换算的等效容差。比较总量具 R&R 的全精度 `%Tolerance`。复核命令、字段及样本均值口径见 [Minitab 单侧规格 P/T](Minitab导入与对标.md#单侧规格-pt)。

## 统计与平台范围

192 组 Minitab 固定基准用于 Xbar-R 原生回归，批量及同组导出实测需启动 Minitab。ANOVA 的计算接口、参考矩阵和复现入口见[ANOVA 设计与五软件对标](ANOVA设计与五软件对标.md)。原生软件界面的参数和已确认差异见[GUI 参数兼容与对标](GUI参数兼容与对标.md)。

本项目采用平衡交叉研究设计。外部软件对照时，请匹配效应模型、估计方法、交互项、研究倍数、容差及历史过程参数。界面尺寸、缩放、颜色和输入核对应记录 Windows 显示设置；OpenGL 像素检查与实际窗口流程分别验收。
