# 字体图集设计与验证

Windows OpenGL 文字渲染使用固定逻辑尺寸分页、最近最少使用（LRU）淘汰和按需分配的 CPU 位图。应用注册完整中文字体，使用 FreeType 采样并按物理像素对齐文字。字体资源加载见[单文件运行验证](单文件运行验证.md)。

## CPU 字形页

- 常规灰度页的逻辑尺寸为 `2048×2048` 单通道，彩色页为 `1024×1024` 四通道，完整页均为 4 MiB；超大字形可使用最大 `4096×4096` 的逻辑页。
- CPU 位图仅分配已需要的行，首次至少分配 64 行，后续按倍增方式扩展至逻辑高度。创建文字实例或仅排版空白文本不预分配完整页，UV 与逻辑页尺寸不随行缓冲扩展而改变。
- 缓存按完整逻辑页的最大像素容量预留 32 MiB 额度，保证页缓冲增长后仍不超过预算；统计中的 `residentBytes` 为实际已分配位图字节。页空间不足时使用新页，达到预算时淘汰最近最少使用页。排版实例保存页标识，不通过共享所有权长期固定旧页。
- 每次提交字形前重新验证页标识。若旧页已被淘汰，按原字体与字形编号重新准备，并更新本次提交的 UV。旧排版几何和物理像素位置不变。
- 单个长文本也按原字符顺序分段提交，不要求整段文字的全部字形同时驻留缓存。因此单次绘制的字形量可以大于缓存预算。
- 正在提交的一段文字会临时保留一个页，防止其像素在同步上传前失效。常规页情况下，缓存外临时保留量最多为一页，即约 4 MiB；字体字节、排版元数据及顶点内存不包含在上述像素缓存预算内。
- 最后一个已初始化文字实例销毁后释放 CPU 图集。显式 `destroy()` 与析构可安全重复，重新创建实例时生成新的页标识。

## OpenGL 纹理与批次

- 每个 OpenGL 上下文独立缓存图集纹理，像素预算为 32 MiB，并检查设备最大纹理尺寸。
- GPU 纹理仍按完整逻辑页分配；更新时只上传 `usedWidth×usedHeight` 的已使用矩形，并包含字形右侧、下侧各 1 像素的透明边缘。该优化减少上传范围，不代表 GPU 页容量变为按需分配。
- 批次同时比较页标识、页内容版本、文字颜色和目标尺寸。不同页可以具有相同版本号，不会被误合并。
- 上传页新内容、切换页或淘汰纹理之前先提交待绘批次，保证旧顶点采样旧页。连续使用同页的字形继续合批，交错页维持原绘制顺序。
- 上下文销毁时释放该上下文的全部文字纹理。窗口之间共用 CPU 页，不共用未验证的 OpenGL 纹理句柄。
- 已生成的保留层存储最终像素，不依赖字形页持续驻留；需要重建保留层时，各文字实例会按页标识自动恢复字形。

## 后备字体与几何一致性

同一中文或 Emoji 后备字体可能被 Noto 正文和等宽主字体共用。共享缓存只复制 UV 与页标识，保留当前主字体计算的基线、字形宽高、前进量和彩色字形缩放。否则不同主字体之间可能出现基线串扰。

## 文本度量缓存

每个固定字号字体面使用 512 槽的字形前进量缓存，约占 6 KiB。它与本地最多 256 条的短文本度量 LRU 分属不同层级，字体支持共享注册和按需回退。

默认字体改变、有效内存字体新增或替换时更新 `fontConfigurationRevision`，使依赖字体配置的缓存失效；相同字节重复注册及无效注册不更新版本。该机制与字形图集页版本分离，字体配置变化不能误复用旧的文字度量。

## 回归方法

独立测试目标为 `msa_text_atlas_tests`，CTest 名为 `msa_text_atlas_regression`。命令参数依次为原始 Noto 字体路径与证据输出目录。

测试创建隐藏的真实 OpenGL 窗口，读取帧缓冲并执行以下检查：

| 场景 | 判据 |
| --- | --- |
| 超过单页容量 | 字体实际覆盖的不同汉字产生多个驻留页 |
| 单次绘制超过缓存预算 | 单个实例含 20,000 个不同汉字与结束标记；确认所有 20,007 个有效字形实际提交，且没有无页或零 UV 字形 |
| 长文本头、中、尾 | 保存三个位置的真实像素；中间字形内部区域与独立短文本参考逐像素一致 |
| 旧实例恢复 | 18、36、38、52 像素字号的原实例不重建文本，淘汰前后像素完全一致 |
| 保留层 | 基准必须含可见文字；缓存命中与释放图形资源后重建均与基准像素一致；通过延迟读回的样本查询逐笔核对矩形覆盖面积，避免中间空帧被最终正常帧掩盖 |
| 分页交错 | 同一文字交错访问多个页，与预热前基准像素一致 |
| 独立页版本号 | 两个不同页的版本号均为 7；预热后延迟合批与逐页立即提交像素一致 |
| 后备字体 | Noto 与等宽主字体分别建立冷缓存基准，两个预热方向及交错复用均保持像素一致 |
| 多上下文 | 两个真实 OpenGL 上下文分别绘制；销毁、重建第二上下文及恢复第一上下文后像素一致 |
| 生命周期与预算 | CPU/GPU 像素缓存不超预算；所有文字实例释放后 CPU 页归零，随后可重新创建并正确绘制 |

输出包括 `text-atlas-regression.json` 和 PPM 帧缓冲证据。`msa_render_regression` 覆盖多个 DPI 下的滚动与小数平移像素一致性，内嵌资源回归检查原字体与共享字体的字节、度量和渲染一致性。

## 内存与渲染范围

CPU 32 MiB 缓存按逻辑页最大容量预留，提交时可暂时持有一个页。页扩容复制、上传像素打包、字体和排版元数据使用额外工作内存。GPU 缓存预算为每个 OpenGL 上下文 32 MiB。

图像与保留层采用 `glBufferData(..., GL_STREAM_DRAW)` 提交流式顶点。像素回归使用 `GL_SAMPLES_PASSED` 记录各次图层绘制覆盖，整帧提交后再读回查询结果。完整测试入口见[验证说明](验证报告.md)。
