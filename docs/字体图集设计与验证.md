# 字体图集设计与验证

本文说明 Windows OpenGL 文字渲染中的字形分页、资源预算和回归方法。完整中文字体、共享内存注册、FreeType 字形采样参数及既有物理像素对齐规则保持不变。

## 问题与处理范围

原文字后端将所有灰度字形放入单个 `2048×2048` 图集。图集用满后，新增字形仍被缓存为成功，但纹理坐标为零，导致部分文字透明消失。不同字号、高 DPI 和不断增加的中文内容会共同消耗图集。

修复采用固定尺寸分页和最近最少使用（LRU）淘汰。它覆盖 CPU 字形准备、布局缓存、OpenGL 纹理缓存和批次提交，避免仅扩大单页尺寸后再次触顶。

## CPU 字形页

- 常规灰度页为 `2048×2048` 单通道，彩色页为 `1024×1024` 四通道，两者通常均为 4 MiB。
- 缓存像素预算为 32 MiB；页空间不足时使用新页，达到预算时淘汰最近最少使用页。排版实例保存页标识，不通过共享所有权长期固定旧页。
- 每次提交字形前重新验证页标识。若旧页已被淘汰，按原字体与字形编号重新准备，并更新本次提交的 UV。旧排版几何和物理像素位置不变。
- 单个长文本也按原字符顺序分段提交，不要求整段文字的全部字形同时驻留缓存。因此单次绘制的字形量可以大于缓存预算。
- 正在提交的一段文字会临时保留一个页，防止其像素在同步上传前失效。常规页情况下，缓存外临时保留量最多为一页，即约 4 MiB；字体字节、排版元数据及顶点内存不包含在上述像素缓存预算内。
- 最后一个已初始化文字实例销毁后释放 CPU 图集。显式 `destroy()` 与析构可安全重复，重新创建实例时生成新的页标识。

## OpenGL 纹理与批次

- 每个 OpenGL 上下文独立缓存图集纹理，像素预算为 32 MiB，并检查设备最大纹理尺寸。
- 批次同时比较页标识、页内容版本、文字颜色和目标尺寸。不同页可以具有相同版本号，不会被误合并。
- 上传页新内容、切换页或淘汰纹理之前先提交待绘批次，保证旧顶点采样旧页。连续使用同页的字形继续合批，交错页维持原绘制顺序。
- 上下文销毁时释放该上下文的全部文字纹理。窗口之间共用 CPU 页，不共用未验证的 OpenGL 纹理句柄。
- 已生成的保留层存储最终像素，不依赖字形页持续驻留；需要重建保留层时，各文字实例会按页标识自动恢复字形。

## 后备字体与几何一致性

同一中文或 Emoji 后备字体可能被 Noto 正文和等宽主字体共用。共享缓存只复制 UV 与页标识，保留当前主字体计算的基线、字形宽高、前进量和彩色字形缩放。否则不同主字体之间可能出现基线串扰。

## 回归方法

独立测试目标为 `msa_text_atlas_tests`，CTest 名为 `msa_text_atlas_regression`。命令参数依次为原始 Noto 字体路径与证据输出目录；测试不依赖外部 AI 服务或真实密钥。

测试创建隐藏的真实 OpenGL 窗口，读取帧缓冲并执行以下检查：

| 场景 | 判据 |
| --- | --- |
| 超过旧单页容量 | 字体实际覆盖的不同汉字产生多个驻留页 |
| 单次绘制超过缓存预算 | 单个实例含 20,000 个不同汉字与结束标记；确认所有 20,007 个有效字形实际提交，且没有无页或零 UV 字形 |
| 长文本头、中、尾 | 保存三个位置的真实像素；中间字形内部区域与独立短文本参考逐像素一致 |
| 旧实例恢复 | 18、36、38、52 像素字号的原实例不重建文本，淘汰前后像素完全一致 |
| 保留层 | 确认实际使用保留层；缓存命中与释放图形资源后重建均与基准像素一致 |
| 分页交错 | 同一文字交错访问多个页，与预热前基准像素一致 |
| 独立页版本号 | 两个不同页的版本号均为 7；预热后延迟合批与逐页立即提交像素一致 |
| 后备字体 | Noto 与等宽主字体分别建立冷缓存基准，两个预热方向及交错复用均保持像素一致 |
| 多上下文 | 两个真实 OpenGL 上下文分别绘制；销毁、重建第二上下文及恢复第一上下文后像素一致 |
| 生命周期与预算 | CPU/GPU 像素缓存不超预算；所有文字实例释放后 CPU 页归零，随后可重新创建并正确绘制 |

输出包括 `text-atlas-regression.json` 和 PPM 帧缓冲证据。已有 `msa_render_regression` 继续覆盖多个 DPI 下的滚动与小数平移像素一致性，内嵌资源回归继续检查原字体与共享字体的字节、度量和渲染一致性。

## 验证状态

2026-10-30，本轮统一 Release 构建及 16 项 CTest 通过。字体专属测试使用真实 OpenGL 帧缓冲，记录 46 次页分配、38 次 LRU 淘汰；旧实例像素、保留层重建、不同主字体回退、多上下文与释放后重建均通过。单次长文本全部 20,007 个有效字形提交、中间位置独立像素参考及同版本不同页合批等断言也通过。

上述结果已包含每上下文缓存设备最大纹理尺寸的最终实现。最终构建完整 16 项 CTest 全部通过，用时 55.93 秒；产物哈希和详细证据见[代码审查修复与回归](代码审查修复与回归.md)。

这里的 CPU 32 MiB 是图集缓存像素预算；提交时可暂时持有一个页。GPU 32 MiB 是每个 OpenGL 上下文的图集纹理预算。两者均不是整个程序的总内存上限。本说明不将静态检查、CPU 准备探针或其它渲染后端的编译兼容等同于真实 OpenGL 像素测试通过。

本轮实现与验收针对项目实际启用的 Windows OpenGL 后端。未运行 Vulkan 或其它操作系统后端的验证，不声明这些后端已通过相同回归。
