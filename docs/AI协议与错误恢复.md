# AI 协议与错误恢复

适用开发版本：**v1.0.0**；AI 回复协议版本：`schema_version=1`。本文说明当前源码的接口约定、状态保护和恢复流程，不作为真实服务测试通过的证据。具体模型、用例、发现与复测范围见[AI 专项验证](AI专项验证.md)；图表及图片/PDF 导出单独见[图表专项验证](图表专项验证.md)。

日常操作见[结果可视化与 AI 助手](结果可视化与AI助手.md)，连接配置见[配置参考](配置参考.md#ai-独立配置)。本功能目前由 GUI 提供，没有对应的 CLI 请求参数。

## 严格结构化输出

AI 辅助生成、失败诊断、澄清问题及结果评价均使用同一套严格 JSON 协议。服务通过 Chat Completions 返回响应，`choices[0].message.content` 必须是**一个完整 JSON 对象**，不能包含 Markdown 代码围栏、JSON 前后的解释文字或第二个对象。GUI 在校验通过后将字段整理为可读内容，不要求用户手动解析 JSON。

所有回复均须包含下列字段；没有问题或提醒时也应保留空数组，不能省略字段。生成任务另含 `config_patch`，解读任务另含 `evaluation`，两者不能混用。

| 公共字段 | 类型与约束 | 作用 |
| --- | --- | --- |
| `schema_version` | 整数 `1` | 协议版本；不能写成字符串 `"1"` |
| `task` | `generate` 或 `interpret` | 必须与本轮请求类型一致 |
| `action` | 按任务限定的字符串 | 区分生成、澄清、诊断和评价 |
| `message` | 非空字符串，最多 8000 字节 | 面向用户的简体中文说明 |
| `questions` | 最多 3 个非空字符串，每项最多 2000 字节 | 需要用户补充的条件；无问题时为 `[]` |
| `warnings` | 最多 8 个非空字符串，每项最多 2000 字节 | 适用前提、数据局限或风险；无补充时为 `[]` |

校验器拒绝未知字段、重复 JSON 键、无效类型、非有限数字、超过 32 层的嵌套、协议版本错误和与任务不匹配的动作。不剥离代码围栏，不从混合文字中截取 JSON，不自动修复模型输出。未通过校验的内容不会加入后续有效助手历史，也不会应用其参数。

请求使用 `response_format={"type":"json_object"}`、`temperature=0.1`、`stream=false` 和 `max_tokens=4096`。DeepSeek 预设同时关闭思考模式。接口或模型不支持所需 JSON 模式时明确报错，不自动降级成自由文本，也不在后台换模型或反复请求。低温度有助于减少输出波动，但不保证相同提示得到完全相同的回复，也不能代替本机校验。

响应的 `choices` 必须恰有一项，该项 `finish_reason` 必须为 `stop`，且正文为字符串。工具调用、函数调用、截断或其他结束方式都不作为有效回复。HTTP 成功和 JSON 语法正确仍不足以证明符合应用字段协议。

### 生成、澄清与失败诊断

| `task` / `action` | `config_patch` | 本机行为 |
| --- | --- | --- |
| `generate` / `generate` | 对象，可为 `{}` | 合并参数并通过完整生成前置校验后启动本机生成；空对象仅在当前配置可执行时有效 |
| `generate` / `clarify` | `null` | 展示追问，`questions` 必须非空；不启动生成 |
| `generate` / `diagnose` | 对象或 `null` | 解释问题；有参数建议时留待用户“按建议重试”，不自动生成 |

`config_patch` 仅允许 `design`、`analysis`、`specification`、`generation`、`target_defaults` 和 `targets` 六个业务字段。具体子字段、枚举和范围遵循[配置参考](配置参考.md)。未指定字段保留当前值；单项指标约束整体替换，避免在切换约束类型后混入旧字段。允许清空的值使用 `null`，不能用空字符串代替数值。

补丁不能修改输出目录、文件名、接口地址、模型、密钥或系统提示词，也不能包含命令、脚本或测量矩阵。模型只建议参数，测量值由本机生成器生成，统计指标和约束由本机复核。参数合法不代表一定能在给定预算内生成成功；搜索失败不等于数学上无解。

### 生成前置检查

生成请求的只读 `msa_context` 顶层包含 `generation_readiness`。该对象由本机根据当前配置计算，并覆盖外部传入的同名值，不能由模型声明替代：

| 字段 | 含义 |
| --- | --- |
| `can_generate` | 当前配置是否通过完整生成前置校验；`true` 不表示已生成成功或必能在搜索预算内成功 |
| `reason` | 前置检查结果，或缺少的条件及约束冲突说明 |

当 `can_generate=false` 时，若用户已给出的信息足以用补丁补齐条件，AI 可以返回 `generate`；否则应返回 `clarify`，请用户提供真实研究条件。不能猜测规格、解除严格规格或暗中放宽目标。模型返回 `generate` 后，本机仍会合并补丁，执行字段、类型、范围校验和 `validate_request` 完整业务校验；在 GUI 应用参数和启动生成前还会再次校验。

`targets` 全部为 `null` 只表示没有额外指标约束，**不能绕过生成前提**。例如，严格规格模式仍至少需要一个规格限；没有双侧规格时仍需有效的参考波动尺度或历史标准差。`config_patch={}` 不会自动填充这些缺失条件：当前配置不可执行时，该回复以 `invalid_config` 拒绝，原配置和数据保留。

`diagnose` 的补丁可以是用于讨论的部分建议，只进行字段、类型和范围校验，不能直接启动生成。用户选择“按建议重试”时，应用前仍须通过完整可执行性校验；建议不完整时继续补足条件。

### 生成回复示例

以下仅为协议语法示例，不是生成成功记录。实际服务正文应只含 JSON 对象，文档中的代码围栏不属于请求或回复内容。

```json
{
  "schema_version": 1,
  "task": "generate",
  "action": "generate",
  "message": "按指定研究设计与规格生成数据，使用当前其余设置。",
  "questions": [],
  "warnings": ["生成的数据用于模拟研究，不能代替现场测量。"],
  "config_patch": {
    "design": {"operators": 3, "replicates": 3, "parts": 10},
    "specification": {"lsl": 9, "usl": 11, "compliance": "strict"},
    "targets": {"GRR_pct": {"mode": "at_most", "value": 20}}
  }
}
```

规格或生成尺度不足、用户条件相互冲突、问题尚不明确时，应先返回 `clarify`，而不是自行补造真实研究条件。生成前还会进行完整业务校验；不合格的建议保留原研究和结果，并显示需要修正的条件。本机失败原因作为后续数据上下文提供，模型不能把“生成成功”等自述当作实际执行结果。上下文含 `last_generation` 时，该次原因分析只能返回 `diagnose` 或 `clarify`；返回 `generate` 会被拒绝。

### 结果评价

| `task` / `action` | `evaluation` | 本机行为 |
| --- | --- | --- |
| `interpret` / `evaluate` | 结构化评价对象 | 校验后展示评价，并按指标键附加本机真实数值 |
| `interpret` / `clarify` | `null` | 展示追问，`questions` 必须非空 |

评价对象的结构固定如下：

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| `conclusion` | 非空字符串，最多 4000 字节 | 总体判断及适用条件 |
| `findings` | 1～5 项对象数组 | 每项仅含 `metric` 和 `assessment`，同一指标不能重复 |
| `findings[].metric` | `EV_pct`、`AV_pct`、`GRR_pct`、`PT_pct`、`ndc` 之一 | 对应本机指标，不允许自定义键或模型生成数值字段 |
| `findings[].assessment` | 非空字符串，最多 2000 字节 | 对该指标的定性解释，不重写指标数值 |
| `recommendations` | 最多 8 个非空字符串，每项最多 2000 字节 | 可执行的改善或补充研究建议 |

指标对应 EV/TV、AV/TV、GRR/TV、P/T 和 ndc。界面显示的对应数值从发送时的本机数据快照读取，模型不能通过新增 `value` 字段替换数值。文字评价仍需结合统计口径阅读；严格 JSON 校验能够限定格式和参数，不能保证模型解释在专业上始终正确。

例如，评价可要求区分重复性、再现性、部件区分能力和规格适用性，并明确生成约束与实际测量系统适用性的区别。模型不能声称执行了新的统计分析，不能将模拟数据当作现场证据，也不应把通用经验阈值写成所有行业的合格标准。

## 多轮会话与状态保护

“AI 辅助生成”和“AI 结果解读”使用独立会话。界面展示用户消息、AI 解读和本机执行结果；发送给模型的助手历史只保留已经校验的协议 JSON。本机生成状态、指标和失败原因单独作为只读上下文，不伪装成模型已经完成的操作。

发送解读请求或在解读模式下“新建会话”，不会清除生成模式的有效诊断建议和本机失败原因。只有新生成请求成功启动、生成模式下新建会话，或研究参数发生变化使建议过期时，才清除相应建议；请求发送前的配置校验失败会保留建议与输入草稿。

每轮请求附带当前研究配置或解读数据快照。用户可先提出基本要求，再逐轮追加方法、精度和指标条件；AI 应保留未要求修改的参数。本机始终对最终补丁进行校验，不因模型尺寸或供应商不同而跳过步骤。小模型与大模型遵守同一协议；模型是否可靠仍需通过其实际多轮案例评估，不能从“OpenAI 兼容”名称推断。

| 情况 | 状态处理 | 继续方式 |
| --- | --- | --- |
| 请求尚未发出即发现配置问题 | 回滚本轮待发送消息，保留输入框内容 | 修正设置后再次“发送” |
| 已发出请求失败或取消 | 保留有效历史与本轮问题，不加入无效助手回复 | 按错误建议修正后“重试本轮”，或输入新的要求 |
| 生成请求等待期间研究参数改变 | 返回的过期参数作废，不自动应用 | 重新描述需求，以当前参数发送 |
| 已保存的生成建议随后失效 | 清除旧建议，不能按旧参数直接重试 | 基于当前研究重新提出需求 |
| 解读所选数据或分析配置改变 | 阻止将新数据混入原会话 | “新建会话”后发送 |
| 解读请求发出后数据改变 | 返回内容明确标记为发送时的旧快照 | 新建会话解读当前数据 |
| 本机生成未找到满足约束的数据 | 保留本机原因，发起一次原因分析；诊断建议不自动执行 | 继续对话，或确认后“按建议重试” |

“重试本轮”重新发送同一轮 AI 请求；“按建议重试”把已通过校验且仍有效的诊断参数交给本机生成器，两者用途不同。修改模型、连接或提示词后，新的请求使用当前 AI 设置；这不允许旧研究参数绕过失效检查。

### 上下文与响应上限

| 项目 | 上限 | 超出后的行为 |
| --- | --- | --- |
| GUI 单条用户输入 | 16000 字节 | 提示精简后发送 |
| 模型会话历史 | 80 条消息，合计 128 KiB；单条 64 KiB | 提示缩短输入或新建会话，不静默删减历史 |
| 序列化请求体 | 256 KiB | 停止发送；提示缩短对话或新建会话 |
| HTTP 响应体 | 2 MiB | 停止接收并报错 |
| 模型回复正文 | 64 KiB | 拒绝过长正文 |
| 请求总超时 | 10～600 秒，默认 120 秒 | 结束请求并提示手动恢复 |

上述消息数包含用户与有效助手历史，不能直接等同为 80 轮对话。长度按 UTF-8 字节计算，中文字数通常小于同一字节上限。协议使用非流式回复；输出达到模型长度上限而被截断时，不应用不完整参数。程序不会通过自动摘要、静默截断、自动修复回复或连续网络重试隐藏此类问题。

## 错误说明与恢复

错误面板提供错误代码、简体中文说明及恢复建议，底部状态栏提供简短反馈。错误分类由程序生成，不直接展示服务端原始错误正文，避免把鉴权信息或无关 HTML 误当作模型答复。错误不是有效助手回复，不会污染后续协议历史。

| 错误代码 / 类别 | 常见原因 | 恢复步骤 |
| --- | --- | --- |
| `request_not_sent`、`invalid_settings`、`missing_api_key` | URL、模型、超时或密钥未满足要求 | 在“AI 配置”修正后手动发送；远程地址使用 HTTPS |
| `http_authentication`、`http_forbidden` | 密钥失效、模型不可访问或账户限制 | 检查账户与模型权限，重新输入密钥；不要把密钥发在对话中 |
| `http_payment` | 服务账户余额或付费状态不可用 | 在服务商侧处理账户状态后手动重试 |
| `http_bad_request`、`json_mode_unsupported`、`http_not_found` | 路径/模型错误，或服务不支持所需请求参数与 JSON 模式 | 选择支持协议的模型/接口；程序不自动放宽要求 |
| `http_redirect` | 接口要求重定向 | 填写可信的最终地址，再输入对应密钥；客户端不自动转发认证信息 |
| `http_rate_limited`、`http_server_error` | 服务限流或暂时不可用 | 等待后手动重试，避免连续点击 |
| `network_error`、`tls_error` | 网络中断、DNS/连接失败或证书无效 | 检查连接及 HTTPS 地址，解决证书问题；不通过关闭校验绕过 |
| `timeout`、`http_timeout`、`cancelled` | 请求耗时过长或用户取消 | 精简问题、适当调整超时，或按需要手动重试 |
| `invalid_json`、`duplicate_key`、`invalid_schema` | 代码围栏、JSON 外文字、重复键、字段或类型错误 | 检查提示词，要求严格按协议回复；必要时更换模型 |
| `invalid_response`、`empty_response`、`truncated_response` | 接口响应结构错误、空正文或输出截断 | 核对 Chat Completions 兼容性，精简要求后重试 |
| `content_filtered` | 服务未提供完整回复 | 检查发送内容，调整需求后重试 |
| `context_limit`、`http_payload_too_large`、`response_too_large` | 请求、上下文或回复超过限制 | 缩短内容或新建会话；服务容量不足时选择合适模型 |
| `invalid_patch` | 补丁字段、类型或范围无效 | 要求 AI 按当前配置提供有效业务参数；原配置保留 |
| `invalid_config`、`invalid_proposal` | 合并建议后仍缺少生成前提，或存在约束冲突 | 补足规格或尺度等条件；不因目标为空而跳过校验，也不静默放宽约束 |
| `invalid_action` | 失败诊断试图自动启动生成 | 要求先解释与建议，确认后再执行 |
| `missing_context`、`invalid_context`、`stale_request`、`invalid_history` | 研究上下文缺失、变化或会话无效 | 重新计算或选择数据，以当前参数发送；必要时新建会话 |
| `diagnosis_unavailable`、`retry_not_sent` | 原因分析或重试未成功发出 | 保留本机原因，修正配置后再发起；切换数据后新建会话 |
| `internal_error`、`http_error` | 其他客户端或服务状态错误 | 按界面建议处理，记录错误代码和复现步骤；不要附带密钥 |
| `models_response_invalid` | 模型列表结构或模型 ID 非法、数量超过上限 | 核对 `/models` 接口兼容性和账户权限，再重新拉取 |
| `balance_unsupported`、`balance_response_invalid` | 当前地址不支持官方余额接口，或余额格式不符合要求 | 使用 DeepSeek 官方预设，或在服务商账户页面核对；不向其他主机转发密钥 |
| `connection_response_invalid` | 连接测试返回的内容不是 JSON 对象 | 选择支持 JSON 对象模式的模型后重试，不降级为自由文本 |

取消请求后，尚未被界面消费的返回参数会被丢弃，不会因网络恰好完成而继续应用。取消本机生成也不会触发自动重试。失败原因分析本身失败时仍保留本机失败信息，可在修正服务配置后重试原因分析。

## 密钥与本地保存

### 模型发现、连接测试与余额查询

“选项 → AI 配置”提供三种独立操作，均使用当前草稿配置、后台线程、总超时和取消机制，不要求先保存，不读取研究数据或对话历史。

| 操作 | 请求与判断 | 恢复方式 |
| --- | --- | --- |
| 拉取 / 刷新模型 | `GET /models`；校验模型 ID 并去重，最多 1024 条，每条不超过 200 字节；不要求事先填写模型 | 接口不支持、无权限或返回空列表时保留原模型，检查地址和账户权限后重试 |
| 测试连接 | 所选模型的 `POST /chat/completions`，非流式 JSON 对象模式；须取得有效 assistant JSON 对象 | 不支持 JSON 模式、空正文、截断或无效 JSON 均不判为成功；更换支持该模式的模型或服务后手动重试 |
| DeepSeek 余额 | 官方 `GET /user/balance`；校验可用标记及各币种金额字符串 | 账户无可用余额时提示检查或充值；非官方自定义服务禁用此入口 |

列表可见、账户有余额和模型可调用是三个不同状态。连接测试发送简短测试消息，可能产生少量费用；测试通过不保证任意业务请求都能通过本机协议和参数校验。测试响应不写入 AI 会话，不触发数据生成。余额只作为本次查询快照显示，不写入配置。

请求中的连接字段暂时锁定，“取消请求”保持可用。请求结果仅适用于发起时的连接配置；配置已变时丢弃旧结果。修改服务、地址或密钥会清除发现缓存及测试状态；修改模型也会清除旧测试状态。取消、失败和空模型列表不会清空原配置，不自动重试，不自动保存，不弹出全局通知。

API Key 由用户在“选项 → AI 配置”输入，项目不内置可用密钥，也不要求将密钥写入源码、命令行、提示词或示例。保存时使用 Windows DPAPI 按当前用户加密，`ai_settings.json` 只存 `api_key_protected` 密文；业务配置、报告与运行日志不保存明文密钥。

DPAPI 是本地保存机制，发起请求时客户端仍需在内存中解密，并通过请求头向用户选定的服务认证。它不等同于匿名访问，也不让业务数据免于传输。跨 Windows 用户或电脑迁移配置后，密文通常不能直接使用，需要重新输入密钥。切换服务类型或修改接口地址都会清空当前密钥，避免发往错误服务。

连接参数与两类系统提示词作为普通配置保存。提示词可以调整专业口径、评价重点和表达风格，不能更改协议字段、要求代码围栏或在 JSON 外追加文字。程序会附加固定协议规则，并在本机再次校验。逐字匹配旧内置默认值的提示词会在加载时升级到当前默认值，自定义提示词保留；升级不自动回写文件。保存配置不会自动发送请求。

生成请求发送研究配置与相关本机状态；解读请求还会发送选定测量数据及本机统计结果。输出目录、文件名和配置中的连接凭据不作为研究上下文发送。用户主动写进普通对话或提示词的内容仍会进入请求，因此不要在这些文本里粘贴密钥。

## 验证边界

协议结构、拒绝规则、取消与重试、多轮生成和解读、DPAPI 保存应分别验证；真实服务结果应记录所用接口、模型、场景与结论，且不记录密钥。某一模型通过不能推定所有兼容接口或所有模型通过；AI 测试也不能替代图表数值、中文显示、组合布局、图片与 PDF 文件的实测。

本文不新增“测试通过”结论，也不改变既有统计内核与外部软件对标报告的适用范围。[AI 专项验证](AI专项验证.md)另行记录实际发现、修正与验证结果。当前版本仍为 v1.0.0；发布状态以仓库明确记录为准。
