# v1.0.0 字体优化与性能验证

2026-10-25，在 Windows x64 Release 构建上对完整内嵌中文字体进行无损压缩、启动后台预加载、共享注册和文本度量缓存优化。最终 EXE 体积缩小、重复文本度量接口明显加快；本机主窗口可见时间及稳态渲染基本持平，固定时点采样的内存略低、累计 CPU 时间增加，不据此承诺程序整体提速或其他设备同样受益。

## 字体完整性与实现边界

- 保留原始`NotoSansCJKsc-Regular.otf`的全部字节，不按静态界面字表裁剪；原字形、字符映射、布局表及 hinting 信息均保留。
- 构建时使用`scripts/pack_font.cpp`和已有 zlib 离线生成`MSAFNTZ1`压缩容器，无需 Python、字体转换工具或在线下载；容器包括各块长度及完整 CRC32。
- 启动阶段在后台预加载字体，将各块并行解码到最终内存并校验完整性，使解码可与窗口及图形环境初始化重叠。解码完成后由 UI 线程注册字体，字体布局和渲染仍在 UI 线程完成。
- 后续调用复用同一个只读共享对象，不重复解码，也不将字体写入临时目录；异步预加载不省略完整性校验或改变原始字体内容。
- 字体注册采用共享所有权，减少完整字体的重复拷贝；回退字体路径按需解析，保留缺字和 emoji 的既有回退机制。
- 文本度量缓存最多 256 条，键包含字体、字号、字重及文本；淘汰和字体更换不改变字符位置、光标映射或显示内容。
- 数据生成、分析算法、约束判断和 CSV 输出规则不因该优化改变。Windows 及 OpenGL 3.3 Core 仍是运行条件，许可证仍随压缩包保留。

## 成品体积

| 对象 | 未压缩内嵌字体构建 | 优化构建 | 减少 |
|---|---:|---:|---:|
| `msa_generator.exe` | 19,491,840 字节（18.59 MiB） | 16,686,592 字节（15.91 MiB） | 2,805,248 字节，14.39% |
| 字体 RCDATA 资源 | 16,437,364 字节 | 13,587,081 字节 | 2,850,283 字节，17.34% |

上表来自实际构建，不采用压缩方案初测的预测值。字体恢复后仍为 16,437,364 字节，变小的是存储表示，不是字符覆盖范围。

ZIP 原本就会压缩字体，因此 EXE 变小不意味着下载 ZIP 按同一比例缩小；本报告不把 EXE 的节省比例当作 ZIP 体积收益。

## 真实进程启动对照

每种构建预热 1 次后交替启动 9 轮，以主窗口首次可见为窗口等待时间的终点。框架在首帧绘制后显示窗口，外部每 5 毫秒检查一次；CPU 和内存统一在首次可见后再等待 150 毫秒采样。因此 CPU 数字是从进程启动到该采样点的累计时间，并非首次可见瞬间的 CPU 开销。这是本机预热启动，不代表所有设备的冷启动表现。

| 指标（9 轮中位数） | 未压缩内嵌字体构建 | 最终异步预加载构建 | 解释 |
|---|---:|---:|---|
| 主窗口首次可见 | 237.1546 ms | 233.4087 ms | 相差约 3.75 ms，与 5 ms 轮询精度同级，基本持平 |
| 进程累计 CPU 时间 | 328.125 ms | 421.875 ms | 可见后 150 ms 采样；并行解码仍消耗 CPU，增加 93.75 ms |
| Working Set | 195,031,040 字节 | 190,562,304 字节 | 该次采样低约 4.26 MiB，不据此承诺所有设备内存均下降 |
| Private Bytes | 144,699,392 字节 | 140,664,832 字节 | 该次采样低约 3.85 MiB，限于此采样条件 |

该结果不支持“整体启动明显更快”或“普遍更省资源”的结论。CPU 时间与用户等待时间是不同指标，后台并行工作可在墙钟时间接近时消耗更多 CPU；本次内存观察也不能代替长时间、多设备验证。

## 字体与渲染微基准

每项取 7 组样本；重复度量每组 10,000 次。渲染测量包含`glFinish`，比较相同文字和绘制流程；没有把耗时阈值作为功能测试通过条件。

| 指标 | 基准 | 优化 | 适用范围 |
|---|---:|---:|---|
| 复制方式注册字体 | 4.5534 ms | 4.4103 ms | 相同接口，基本接近 |
| 共享方式注册字体 | 不适用 | 0.3463 ms | 应用采用的共享路径，避免完整字体再次复制 |
| 首次文本度量 | 0.6366 ms | 0.3601 ms | 局部操作测量 |
| 重复文本度量 | 69.32842 µs/次 | 0.23230 µs/次 | 缓存命中接口约 298 倍加速，不能换算为整个软件的加速倍数 |
| 重复尺寸测量 | 0.12146 µs/次 | 0.11993 µs/次 | 基本持平 |
| 首次渲染帧 | 7.0282 ms | 6.9718 ms | 基本持平 |
| 稳态渲染帧 | 0.3586 ms | 0.3547 ms | 基本持平，不作为用户可感知提速的证明 |

同步调用解码组件的微基准中，一次解码的中位数为 16.5357 ms，首次内嵌字体加载为 16.5690 ms；后续已缓存字体获取约 0.01507 µs/次，复用同一对象。最终应用另在启动阶段后台预加载，真实进程表现以上述 9 轮对照为准。压缩带来的一次解码成本没有被隐藏，也不能仅凭并行解码快于串行解码就认定启动快于未压缩构建。

## 正确性回归

最终构建 7 项 CTest 全部通过；CLI 为 89 项检查、发布校验为 17 项检查。内嵌资源专项确认：

- 压缩资源恢复的完整字体字节与锁定原文件相同，CRC32 及 SHA-256 核对一致。
- 损坏、截断、长度错误、尾随数据和校验和错误的容器被拒绝。
- 调用方释放注册缓冲后字体仍有效；共享对象、解码缓存和重复注册生命周期正确。
- 在空工作目录中，14、18、24、28 四种字号的文字度量和实际像素与原字体相同，包含`龘𠮷`及 emoji 回退样本。
- 300 条不同度量记录触发 256 条有界缓存的逐出，复核宽度、字符索引和光标位置保持正确。

优化 EXE 已通过真实单文件窗口验收：中文及罕见字模板显示正常，90 条随机长表导出与同配置 CLI 逐字节一致，StdOrder 完整，未产生字体文件且未改个人配置。记录见[单文件运行验证](单文件运行验证.md)。Minitab 对标文档保留其执行时的二进制哈希；该字体专项没有改动统计内核，也没有将既有实测转记为新 EXE 再次执行的证据。

## 复现与证据

启用桌面测试后构建并运行常规回归与优化字体微基准：

```powershell
cmake -S . -B build -A x64 -DMSA_BUILD_RENDER_TESTS=ON
cmake --build build --config Release --parallel 6
ctest --test-dir build -C Release --output-on-failure
.\build\Release\msa_font_performance.exe ".\resources\fonts\NotoSansCJKsc-Regular.otf" ".\build\font-performance\optimized.json"
```

对照目标`msa_font_performance_baseline.exe`仅在本地保留对应基准库时生成；对比必须使用相同机器、样本和渲染设置，不以缺失该可选目标判断正常构建失败。

机器证据位置：

- `build/embedded-test-output/embedded-resources.json`：无损恢复、错误输入、生命周期、缓存逐出及像素回归。
- `build/font-performance/baseline.json`、`build/font-performance/optimized.json`：字体注册、度量、解码及渲染微基准。
- `build/font-performance/startup-selected/startup-benchmark.json`：最终异步预加载方案的 9 轮对照，包含窗口可见时间、CPU、内存、执行顺序及被测 EXE 哈希；CPU 及内存在首次可见后 150 ms 采样。

最终异步预加载 EXE SHA-256：`C8411E4F5CBC3F75D117CC948FD45A6C1FC7BD8120C3A751C49C0FD06D6C9C56`。对照二进制的完整标识保留在上述机器报告中，不作为当前发行 EXE 的校验值。

性能数字受磁盘缓存、系统负载、驱动及硬件影响；本报告说明列明环境下的观察及取舍，不承诺其他机器的耗时。所有完整机器报告和临时基准由`.gitignore`排除，源码保留测试入口和构建辅助工具。
